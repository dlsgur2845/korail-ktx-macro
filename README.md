# KTX 잔여석 매크로

코레일 일반 예매 웹에서 원하는 KTX 좌석을 감시하고, 좌석 선택과 예매 요청을 보조하는 Chrome 확장 프로그램입니다. **결제는 직접 진행합니다.** 명절 전용 예매 사이트는 지원하지 않습니다.

현재 버전 **1.8.3** · [릴리스 노트](RELEASE_NOTES.md)

## 설치·업데이트

1. 저장소 또는 배포 ZIP을 내려받아 압축을 풉니다.
2. Chrome의 `chrome://extensions`에서 **개발자 모드**를 켭니다.
3. **압축해제된 확장 프로그램 로드**로 `manifest.json`이 있는 폴더를 선택합니다.
4. 코레일 탭을 새로고침합니다.

업데이트: **감시 중지 → 기존 폴더 파일 교체 → 확장 프로그램 새로고침 → 코레일 탭 새로고침**.

사용에는 Node.js·Python 등 별도 프로그램이 필요하지 않습니다. 자동 클릭에 `debugger`, PC 알림에 `notifications`, 휴대폰 알림 설정 저장에 `storage` 권한을 사용합니다. 자동 실행 중에는 Chrome 개발자 도구를 닫아주세요.

## 사용 방법

1. 코레일에 로그인하고 편도 날짜·구간·인원을 지정해 열차를 조회합니다.
2. **특정 열차** 또는 **시간대** 중 하나를 감시 기준으로 선택합니다. 열차 번호는 여러 개 입력하거나 목록에서 선택할 수 있습니다.
3. 좌석 등급·발견 시 동작을 고르고 **감시 시작**을 누릅니다.
4. 알림이 오면 예약 내역과 결제 기한을 확인하고 직접 결제합니다.

상단 카드에서 대상 열차·출발 시각·구간을 확인할 수 있습니다. `−` 버튼으로 최소화해도 감시는 계속됩니다.

## 예약대기

**예매 · 예약대기 신청** 모드에서는 현재 읽은 목록의 좌석을 우선하고, 좌석이 없으면 조건에 맞는 예약대기를 신청합니다. **접수 완료가 확인되면 정지하고 소리·PC·연결된 ntfy로 알립니다.** 예약대기는 좌석 확보로 집계하지 않습니다.

신청 인원은 항상 1명입니다. 배정 여부와 결제 기한은 코레일에서 직접 확인하세요. 코레일의 선택 사항인 휴대폰 번호·개인정보 동의는 자동으로 켜지 않으며, ntfy는 접수 알림만 보내고 이후 배정을 감시하지 않습니다.

## 두 번째 사람 예약

코레일 웹에서도 **1명**으로 조회합니다. 한 번 접수하면 정지하고 알리며, 자동으로 두 번째 예약을 시도하지 않습니다.

다른 1명이 필요하면 코레일에서 기존 예약·예약대기 결과를 확인한 뒤 조회 화면으로 돌아와 **기존 접수 유지하고 다음 1명 시작**을 누르세요. 확인창에 동의하면 현재 감시 조건으로 새 시도를 시작합니다. 기존 실제 접수를 취소하거나 변경하지 않습니다. 같은 열차가 필요하면 해당 번호만 선택하세요. 같은 열차의 추가 예약대기를 코레일에서 거절하면 자동 우회하지 않습니다.

결과가 불명확한 시도도 이 버튼으로 이어갈 수 있지만, 먼저 실제 내역을 확인해야 합니다. 이전 여러 장 설정은 업데이트 시 자동 재개하지 않습니다. 실제 서버의 추가 1명 접수는 아직 미검증입니다.

## 동작 기준

선택한 열차의 지연(지연배상 없음)·우회·단체 위약금 안내·좌석 자동배정은 자동으로 동의·확인합니다. 조회는 브라우저 일반 새로고침(F5에 해당)을 사용하며 별도 설정이 필요하지 않습니다.

- 특정 열차는 최초 목록과 더보기 최대 2회까지 찾습니다. 시간대는 종료 시각을 포함하는 범위까지 더보기를 진행합니다. 웹 조회 시작 시각보다 앞선 열차는 검사할 수 없습니다.
- 특정 열차 모드는 선택한 번호를 기준으로 하며 인접역 열차도 포함할 수 있습니다. 시간대 모드는 조회 구간과 출발 시간대를 함께 확인합니다.
- 예약대기 신청 후 정확히 **예약대기자한도수초과** 안내가 나오면 확인을 누르고 같은 선택의 예약대기신청만 다시 시도합니다. 새로고침하지 않으며, 응답과 안내창 종료를 기다리고 최소 1초 간격을 둡니다. 개인별 신청 제한·로그인·결과 불명은 반복하지 않습니다.
- 좌석을 발견하면 해당 열차에 집중합니다. 명확한 **잔여석 없음** 안내는 닫고 같은 선택을 유지해 예매만 재시도합니다.
- 예매 결과가 불명확하거나 서버 오류·로그인·접근 제한 안내가 있으면 정지합니다. 결제나 알 수 없는 안내창은 자동 처리하지 않습니다.
- 조회 오류 시 대기 시간을 늘려 복구를 시도합니다. 조회 후 대기와 쉬어가기는 추가 설정에서 변경할 수 있습니다.

## 알림

**PC:** 알림 설정에서 테스트할 수 있습니다. Chrome 알림 허용 및 운영체제의 집중 모드 설정을 확인해주세요.

**휴대폰:** **알림 설정 → 휴대폰 알림 연결 · ntfy**를 엽니다.

1. 휴대폰에 [ntfy 앱](https://docs.ntfy.sh/subscribe/phone/)을 설치하고 알림을 허용합니다.
2. 서버 `https://ntfy.sh`와 연결 화면의 주제 이름으로 구독합니다.
3. PC에서 휴대폰 알림 사용을 켜고 저장한 뒤 테스트 알림을 보냅니다.

ntfy 연결 권한은 켤 때만 요청합니다. 주제 이름을 아는 사람은 알림을 읽거나 보낼 수 있으므로 공유하지 마세요. 열차 번호·출발일·구간·출발시각·좌석 등급·처리 결과·재시도 횟수와 분류된 중지 사유를 전송합니다. 예약번호·계정 정보·쿠키·오류 원문은 보내지 않습니다. 서버 전송 성공과 휴대폰 수신은 별도로 확인해야 합니다.

## 참고

- 실행 중에는 PC와 Chrome을 켜두세요. 절전·탭 종료·로그인 만료에 영향을 받습니다.
- 감시 조건·실행 상태·현재 시도 기록는 탭의 세션 저장소에, ntfy 설정은 확장 프로그램의 로컬 저장소에 저장됩니다. 다른 PC에는 자동 동기화되지 않습니다.
- Chrome에서 화면과 일부 동작을 검증했습니다. 실제 매진 경쟁 상황의 좌석 확보를 보장하지 않습니다.
- 개발용 테스트: Node.js 환경에서 `npm test`.


## 지속 로그 파일 (1.7.0)

조회·좌석 발견·클릭·예매 요청 응답·중지·내부 오류를 확장 프로그램 전용 로컬 파일 저장소(OPFS)에 JSONL로 기록합니다. Chrome을 닫거나 PC를 재시작해도 보존되며, 새 버전을 로드한 이후 기록부터 저장합니다. 패널의 **진행 기록 → 로그 파일 · 내려받기**에서 파일별로 내려받을 수 있습니다. 일반 탐색기 폴더에 직접 저장하는 방식은 아닙니다.

- 크기 기준: UTF-8 기준 **10 MiB(10,485,760바이트)**. 다음 기록으로 한도를 넘기면 현재 파일을 gzip 압축하고 새 파일에 기록합니다.
- 날짜 기준: 한국 날짜가 바뀐 파일은 gzip 압축합니다. 기록할 때와 매시간 정리하며, Chrome이 꺼져 있으면 다음 실행 때 처리합니다.
- 압축 성공 후 원본 JSONL만 제거하고 압축본은 자동 삭제하지 않습니다. 압축 실패 시 원본을 유지합니다. 저장 공간은 계속 증가할 수 있습니다.
- 로그 기록은 순서대로 처리하고 자동 새로고침 전에 대기 중인 파일 쓰기를 기다립니다. 갑작스러운 강제 종료 직전 아직 전달되지 않은 기록은 누락될 수 있습니다.
- 쿠키와 요청 본문은 수집하지 않습니다. 열차 번호·오류 문구가 포함될 수 있습니다. 확장 프로그램 제거·브라우저 저장 데이터 삭제 시 로그도 삭제됩니다.
- 로컬 파일 저장소: https://developer.chrome.com/docs/capabilities/web-apis/file-system-access#accessing_the_origin_private_file_system / gzip: https://developer.mozilla.org/en-US/docs/Web/API/Compression_Streams_API


## 로그 삭제 (1.7.1)

로그 파일 목록에서 내려받기 옆 **삭제**를 누르고 파일명을 확인하면 해당 파일을 **완전삭제**합니다. 시스템 휴지통으로 보내지 않으며 복원할 수 없습니다. 취소하면 삭제하지 않습니다. Windows·Mac의 Chrome에서 같은 확장 프로그램 저장소 API를 사용합니다. 이미 내려받은 파일에는 영향을 주지 않습니다. 기록 중인 파일을 삭제하면 이후 기록은 새 파일에 저장됩니다. 현재 화면의 최근 진단 기록과 lastError는 별도의 탭 세션 데이터이므로 파일 삭제로 지워지지 않습니다. 두 OS의 실제 브라우저 검증은 하지 않았으며 파일 삭제·동시 쓰기·확인/취소·권한 제한 모의 테스트를 통과했습니다.


## 상세 진단 로그 (1.7.2)

기록만으로 모든 오류를 자동 수정하지는 않습니다. 로그를 통해 실패 위치를 구분하고 원인을 분석할 수 있도록 다음 정보를 추가했습니다.

- 실행 ID·문서 ID·연속 순번·발생 시각(eventAt)·저장 수신 시각(at). 자동 새로고침 시 실행 ID와 순번을 유지하고 수동 시작 시 새 실행 ID를 생성합니다.
- 좌석 등급·열차 번호·예매 단계와 단계 경과 시간·요청 응답 관측 여부. /web_r/ 타이밍 관측은 정확한 업무 요청 종류나 서버 내부 실패 원인을 보장하지 않습니다.
- 클릭 준비/위치 확인/전송/이벤트 확인 단계, 버튼명·활성/연결 상태·좌표·뷰포트·가림 여부, Chrome 입력 처리 세부 실패 단계와 원래 오류 사유.
- 중지 이유·예매 종료 이유·안내창 분류/문구/버튼·조회 HTTP 상태·페이지 종류·오류 이름·코드 줄/열 위치.
- 팝업 문구는 최대 1,200자만 기록합니다. URL·이메일·일반적인 전화번호와 예약번호 표기를 가립니다. 임의 형식의 개인정보까지 완벽하게 가려지는 것은 아니므로 외부 공유 전 로그를 확인하세요. 쿠키·요청/응답 본문·전체 페이지 HTML은 수집하지 않습니다.

HTTP 200은 예매 성공 판정이 아닙니다. 상세 로깅은 기존 재시도·정지 정책을 바꾸지 않습니다. 업데이트 이전 로그에 없던 정보는 복구되지 않습니다.
